# Wiki hygiene

## MUST NOT
- Record history, a diary, or a superseded decision in the wiki — the wiki holds current-state only; git history is the diary.
- Leave a wiki entry stale after a change resolves, contradicts, or supersedes what it documents — update it in the same pass as the code change, not as a follow-up.
- Resolve a documented "Open decision" silently — record the resolution and remove the open-decision note in the same pass, and if it was a judgment call rather than a settled requirement, say so.
- Leave a wiki entry in place once it's no longer referenced by any code or by another wiki file — prune or merge it.
- Skip the weekly category-4 context audit's findings — stale entries and size/performance flags it raises get triaged, not ignored.
