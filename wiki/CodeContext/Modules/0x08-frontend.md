# 0x08 — Frontend

**Agent-facing.** Current-state only — see [[wiki/GeneralContext/index|index]] for how this wiki is organized.

The React SPA. Backend module contracts live in `0x01`–`0x07`; this file records
what the frontend does with them, and nothing that belongs to a backend module.

## State

**Foundation, authentication, the profile page, the composer, the notifications
view, the feed, search, the game page, the Stats and player pages, and the thread modal** (`FRONTEND-001` … `FRONTEND-010`). No placeholder
view is left.

What is real:

Since `FRONTEND-024`, `components/ui/EmptyState` places the decorative
`CourtScoreboard` SVG before its unchanged message. The empty feed and player
search use it; public profiles show "No posts yet." and record cards without a
qualifying holder retain their copy alongside the same motif. The SVG is
hidden from assistive technology and uses the semantic theme tokens.

## Contracts the foundation pins

Changed only with the tests that pin them, because six later units build on
each:

- **Routes**: `/`, `/compose`, `/notifications`, `/search`, `/profile/:userId`,
  `/sign-in`, `/sign-up`, `/confirm`, `/forgot-password`, and `*`, plus
  `/create-profile` from `FRONTEND-002`. The catch-all is the app's own
  not-found view — deliberately, so react-router's built-in error element can
  never stand in for a view the app does not have and make a missing route read
  as green. `routes.test.tsx` sweeps every route asserting no *other* view's
  heading is on screen, so the headings are pinned and anchored; since
  `FRONTEND-002` the sweep also records which of the three guard states makes
  each route the one that renders.
- **Client surface**: `createApiClient(provider)` (the factory a test double is
  injected through), the `apiClient` singleton the app uses, and
  `setTokenProvider(provider)`. The singleton reads the *current* provider
  through a closure, so `FRONTEND-002` can install the real Cognito one after
  module load.
- **No `Authorization` header at all** when the provider returns null — not an
  empty one. `Bearer null` and `Bearer ` both make the backend verifier 401 an
  anonymous request, which breaks the guest feed for a reason nobody would look
  for.
- **`config.ts` exports one `config` object**, throws at module load, and names
  *every* missing variable rather than the first.
- **The base URL is resolved against `window.location.origin`.** `/api` handed
  straight to `createClient` throws `Invalid URL` from Node's `Request`
  constructor under vitest, before msw sees it. Same origin either way — this
  changes nothing about the deployed contract and adds no CORS.

## Settled contracts

These are decided and are not re-litigated by a unit that finds them
inconvenient:

- **API base URL** is `VITE_API_BASE_URL` = `/api`, same origin in both
  environments. Vite's `server.proxy` strips `/api` in dev; a CloudFront Function
  strips it in production ([[0x00a-architecture-infra]] "Frontend ↔ API contract").
  There is no CORS anywhere and none is to be added.
- **Types are generated**, never hand-written: `openapi-typescript` produces
  `src/api/schema.d.ts` from `backend/openapi.json`, and `openapi-fetch` is the
  only HTTP client.
- **Auth is real Cognito** — a hand-made dev pool locally, `Fanwire-Auth`'s pool
  in production. Never an emulator or an in-house fake. The SPA sends the
  **ID token** as `Authorization: Bearer`; the backend rejects access tokens
  ([[0x01b-users-auth]]).
- **A 404 from `GET /users/me`** means "authenticated, no profile yet" and routes
  to profile creation. It is a state, not an error. When such an authenticated
  user lands on `/`, `AppLayout` redirects to `/create-profile`; an anonymous
  visitor still sees the guest feed without a profile lookup.
- Email verification is optional for sign-in and core account use. The account
  settings action restores and validates the current Cognito SDK session before
  requesting a verification code, and completes only after the SDK reports its
  successful code-entry callback. Cognito's signup delivery and verified-state
  result remain a dev-pool acceptance check.
- **Date of birth is private**: the user's own profile and settings only, never a
  public profile view.
- **Configuration is read in exactly one module** (`src/config.ts`), which
  validates at load and throws on a missing value. Vite inlines `VITE_*` at build
  time, so the production bundle is only correct for the environment it was built
  against: the production Cognito ids don't exist until `Fanwire-Auth` deploys
  ([[wiki/CodeContext/Standards/build-deployment-spa|Rebuilding the SPA]]).
